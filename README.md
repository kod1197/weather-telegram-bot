# Weather CLI

Простой Python-скрипт для получения текущей погоды по названию города.
Скрипт использует Open-Meteo и не требует API-ключа.

## Быстрый старт

Показать погоду для города:

```bash
python3 weather.py Москва
```

Для названий из нескольких слов можно использовать кавычки или передать слова отдельно:

```bash
python3 weather.py "New York"
python3 weather.py New York
```

Если город не передан аргументом, скрипт спросит его интерактивно:

```bash
python3 weather.py
```

## Требования

- Python 3.10 или новее.
- Доступ в интернет для реального запроса погоды.
- Внешние Python-пакеты не нужны.
- Для Telegram-бота используется SQLite из стандартной библиотеки.

## Что выводит скрипт

Успешный пример:

```text
Погода: Москва, Москва, Россия
Время: 2026-07-02T15:45
Сейчас: переменная облачность
Температура: 30.2 °C
Ощущается как: 30.2 °C
Влажность: 36 %
Ветер: 9.6 km/h
```

При ошибке сообщение печатается в `stderr`, а код выхода равен `1`:

```text
Ошибка: нужно указать название города, а не число или индекс
```

## Правила ввода города

Скрипт ожидает именно название города.

Допустимо:

```bash
python3 weather.py Москва
python3 weather.py "Санкт-Петербург"
python3 weather.py "St. Petersburg"
```

Недопустимо:

```bash
python3 weather.py 123
python3 weather.py "Москва 123"
python3 weather.py ---
```

Числовой ввод запрещен намеренно: Open-Meteo Geocoding умеет искать почтовые индексы,
а этот скрипт должен работать только с названиями городов.

## Как работает

Поток выполнения:

1. `main()` читает аргументы командной строки через `parse_args()`.
2. Если город не передан, `main()` запрашивает его через `input()`.
3. `find_city(city)` валидирует название через `validate_city_name(city)`.
4. `find_city(city)` обращается к Open-Meteo Geocoding API и берет первый результат.
5. `get_weather(place)` запрашивает текущую погоду по координатам найденного места.
6. `format_weather(place, weather)` превращает ответ API в человекочитаемый текст.
7. `main()` печатает результат в `stdout` или ошибку в `stderr`.

## Внешние API

Используются два endpoint:

- `https://geocoding-api.open-meteo.com/v1/search` для поиска координат по названию города.
- `https://api.open-meteo.com/v1/forecast` для получения текущей погоды по координатам.

Запрашиваемые текущие погодные поля:

- `temperature_2m`
- `apparent_temperature`
- `relative_humidity_2m`
- `weather_code`
- `wind_speed_10m`

Параметр `timezone=auto` нужен, чтобы время в ответе было локальным для найденного города.

## Структура файлов

- `weather.py` - основной CLI-скрипт.
- `bot.py` - Telegram-бот, который использует функции из `weather.py`.
- `test_weather.py` - unit-тесты.
- `test_bot.py` - unit-тесты Telegram-обертки.
- `TEST_REPORT.md` - краткий отчет по тестированию.
- `.env.example` - пример переменной окружения с токеном Telegram-бота.
- `deploy/weather-bot.service` - unit-файл для запуска бота через systemd.
- `README.md` - эта документация.

## Telegram-бот

Бот работает через long polling и не требует публичного webhook URL. Это удобно для
первого запуска на сервере: нужен только исходящий доступ к Telegram API и Open-Meteo.

Токен передается только через переменную окружения:

```bash
export TELEGRAM_BOT_TOKEN="ваш_токен"
python3 bot.py
```

Поведение бота:

- `/start` и `/help` показывают короткую инструкцию.
- Любой обычный текст считается разовым запросом погоды по городу.
- `/setcity Москва` сохраняет город по умолчанию.
- `/settime 08:30` включает ежедневную отправку погоды.
- `/stopnotify` отключает ежедневную отправку.
- `/city` показывает сохраненный город.
- `/weather` показывает погоду для города по умолчанию.
- `/weather Москва` показывает разовую погоду для указанного города.
- Числа и строки с цифрами отклоняются теми же правилами, что и CLI.
- Ответ с погодой формируется через `find_city`, `get_weather` и `format_weather`.
- В ответах Telegram используются эмодзи для основных погодных полей.
- При старте бот регистрирует меню команд Telegram через `setMyCommands`.
- Каждый ответ бота отправляется с постоянной reply-клавиатурой через `reply_markup`.

В стандартном меню команд Telegram отображаются команды:

- `/weather` - погода для города по умолчанию.
- `/setcity` - сохранить город по умолчанию.
- `/settime` - настроить ежедневную рассылку.
- `/stopnotify` - отключить ежедневную рассылку.
- `/city` - показать сохраненный город.
- `/help` - справка.

В reply-клавиатуре под полем ввода отображаются кнопки:

- `🌤 Погода` - показать погоду для города по умолчанию.
- `🏙 Настроить город` - начать настройку города по умолчанию.
- `📍 Мой город` - показать сохраненный город.
- `⏰ Настроить рассылку` - выбрать время ежедневной погоды.
- `🔕 Отключить рассылку` - выключить ежедневную погоду.
- `ℹ️ Помощь` - показать справку.

Кнопка `🏙 Настроить город` запускает короткий диалог: бот просит написать город,
следующее обычное текстовое сообщение сохраняется как город по умолчанию.
Reply-клавиатура появляется после нового сообщения от бота, например после `/start`.

Кнопка `⏰ Настроить рассылку` запускает диалог настройки времени. Пользователь
вводит время в формате `ЧЧ:ММ`, например `08:30`, и бот каждый день отправляет
погоду по сохраненному городу. Время считается в timezone сохраненного города,
если Open-Meteo вернул его при поиске города; иначе используется `UTC`. Бот хранит
`last_notification_date`, чтобы не отправить ежедневную погоду дважды за один день.

Настройки пользователей хранятся в SQLite. Путь по умолчанию:

```text
data/weather-bot.sqlite3
```

Путь можно переопределить переменной окружения:

```bash
export WEATHER_BOT_DB=/opt/weather-bot/data/weather-bot.sqlite3
```

В таблице `user_settings` хранятся настройки ежедневной отправки:
`notification_enabled`, `notification_time`, `timezone`, `last_notification_date`.
Если у уже сохраненного города нет timezone, бот при настройке рассылки пробует
обновить данные города через geocoding.

### Запуск через systemd

Рекомендуемая раскладка на сервере:

```text
/opt/weather-bot/
  bot.py
  weather.py

/etc/weather-bot.env
/etc/systemd/system/weather-bot.service
```

Файл `/etc/weather-bot.env`:

```env
TELEGRAM_BOT_TOKEN=ваш_токен
WEATHER_BOT_DB=/opt/weather-bot/data/weather-bot.sqlite3
```

Права на env-файл должны быть ограничены:

```bash
chmod 600 /etc/weather-bot.env
```

Команды управления:

```bash
systemctl daemon-reload
systemctl enable --now weather-bot
systemctl status weather-bot
journalctl -u weather-bot -f
```

Unit-файл лежит в `deploy/weather-bot.service`.

## Контракты функций для ИИ-агента

`validate_city_name(city: str) -> None`

- Проверяет пользовательский ввод до обращения к API.
- Успешно завершается для строк, где есть хотя бы одна буква и нет цифр.
- Бросает `WeatherError`, если строка состоит не из названия города.
- Не должна делать сетевых запросов.

`get_json(url: str, params: dict[str, Any]) -> dict[str, Any]`

- Кодирует `params` в query string через `urlencode`.
- Делает GET-запрос с timeout `10` секунд.
- Возвращает распарсенный JSON как `dict`.
- Преобразует `HTTPError`, `URLError` и `TimeoutError` в `WeatherError`.

`find_city(city: str) -> dict[str, Any]`

- Сначала вызывает `validate_city_name(city)`.
- Запрашивает Geocoding API с `count=1`, `language=ru`, `format=json`.
- Возвращает первый объект из `results`.
- Бросает `WeatherError`, если город не найден.
- Для недопустимого ввода не должна вызывать `get_json`.

`get_weather(place: dict[str, Any]) -> dict[str, Any]`

- Ожидает, что `place` содержит `latitude` и `longitude`.
- Запрашивает Forecast API.
- Возвращает полный JSON-ответ прогноза.

`format_weather(place: dict[str, Any], weather: dict[str, Any]) -> str`

- Ожидает, что `weather["current"]` является словарем.
- Использует `weather["current_units"]`, если единицы измерения есть в ответе.
- Возвращает многострочный текст для вывода пользователю.
- Бросает `WeatherError`, если формат ответа неожидан.

`main() -> int`

- Возвращает `0` при успехе и `1` при ошибке.
- Печатает успешный результат в `stdout`.
- Печатает пользовательские ошибки в `stderr`.
- Ловит только `WeatherError`; неожиданные ошибки должны оставаться видимыми при разработке.

## Контракты Telegram-бота для ИИ-агента

`telegram_request(token: str, method: str, params: dict | None = None, timeout: int = 10) -> Any`

- Делает POST-запрос к Telegram Bot API.
- Возвращает поле `result` из успешного ответа.
- Преобразует HTTP, сетевые ошибки и `ok=false` в `BotError`.
- Не должен логировать token.

`set_bot_commands(token: str) -> None`

- Регистрирует стандартное меню команд Telegram через `setMyCommands`.
- Использует `BOT_COMMANDS` как единственный источник списка команд.
- Вызывается при старте `run_polling` после `deleteWebhook`.

`build_main_keyboard() -> dict`

- Возвращает Telegram `ReplyKeyboardMarkup` для постоянной клавиатуры под полем ввода.
- Используется в каждом `sendMessage`.
- Содержит основные действия без необходимости вручную писать slash-команды.

`init_database(db_path: str) -> None`

- Создает SQLite-файл и таблицы `user_settings`, `user_state`, если их еще нет.
- Таблица хранит `chat_id`, город по умолчанию, координаты и настройки ежедневной отправки.
- `user_state` хранит текущий короткий диалог, например ожидание города после кнопки настройки.
- При старте выполняет мягкую миграцию и добавляет `last_notification_date`, если колонки еще нет.
- Не делает сетевых запросов.

`save_default_city(chat_id: int, place: dict, db_path: str) -> None`

- Сохраняет или обновляет город по умолчанию для Telegram-чата.
- Хранит координаты, чтобы `/weather` не делал повторный geocoding.
- Не изменяет поля будущих уведомлений.

`get_default_city(chat_id: int, db_path: str) -> dict | None`

- Возвращает сохраненный город как `place`-совместимый словарь.
- Возвращает `None`, если город еще не выбран.

`parse_notification_time(value: str) -> str`

- Принимает время в формате `ЧЧ:ММ`.
- Нормализует `8:30` в `08:30`.
- Бросает `ValueError`, если время невалидно.

`set_notification_schedule(chat_id: int, notification_time: str, db_path: str) -> None`

- Включает ежедневную отправку для сохраненного города.
- Сбрасывает `last_notification_date`, чтобы новая настройка начала действовать свежо.
- Бросает `BotError`, если город по умолчанию еще не выбран.

`refresh_default_city_timezone(chat_id: int, db_path: str) -> None`

- Для старых записей без timezone пытается заново найти сохраненный город.
- Обновляет timezone и координаты через `save_default_city`.
- Используется при настройке времени рассылки.

`disable_notifications(chat_id: int, db_path: str) -> bool`

- Отключает ежедневную отправку и очищает время.
- Возвращает `False`, если настроек пользователя еще нет.

`get_due_notifications(db_path: str, now: datetime | None = None) -> list[dict]`

- Возвращает пользователей, которым пора отправить ежедневную погоду.
- Сравнивает текущее время с `notification_time` в timezone сохраненного города.
- Не возвращает пользователя повторно, если `last_notification_date` уже равен сегодняшней локальной дате.

`process_due_notifications(token: str, db_path: str) -> None`

- Отправляет ежедневную погоду всем due-пользователям.
- После успешной отправки записывает `last_notification_date`.
- Не должен ронять основной polling-цикл из-за ошибки одного пользователя.

`build_response_text(text: str, chat_id: int, db_path: str | None = None) -> str`

- Возвращает справку для `/start` и `/help`.
- Обрабатывает `/setcity`, `/city`, `/weather`, `/settime`, `/stopnotify`.
- Обрабатывает кнопки reply-клавиатуры.
- Для `🏙 Настроить город` сохраняет состояние ожидания города в `user_state`.
- Для `⏰ Настроить рассылку` сохраняет состояние ожидания времени в `user_state`.
- Возвращает сообщение о неизвестной команде для других команд.
- Для обычного текста вызывает погодные функции и предлагает сохранить город.
- Пользовательские ошибки погоды возвращает как текст с префиксом `Ошибка:`.

`handle_update(token: str, update: dict) -> None`

- Обрабатывает только текстовые `message`.
- Игнорирует нетекстовые сообщения и неизвестные update-типы.
- Отправляет ответ в тот же `chat.id`.

`run_polling(token: str) -> None`

- Отключает webhook через `deleteWebhook`, потому что long polling и webhook взаимоисключающие.
- Регистрирует меню команд Telegram через `set_bot_commands`.
- Получает update через `getUpdates`.
- Проверяет due-рассылки после каждого long polling цикла.
- Сдвигает `offset`, чтобы Telegram не присылал уже обработанные сообщения повторно.
- Не должен завершать процесс из-за одной пользовательской ошибки.

## Тесты

Запуск всех тестов:

```bash
python3 -m unittest -v
```

Тесты не ходят в сеть. Внешние вызовы замоканы, поэтому проверки быстрые и стабильные.

Покрытые сценарии:

- валидные и невалидные названия городов;
- запрет числового ввода вроде `123`;
- кодирование параметров URL;
- обработка HTTP-ошибок и сетевых ошибок;
- поиск города;
- запрос прогноза по координатам;
- форматирование ответа;
- CLI-ветки успеха и ошибок;
- Telegram-команды, отправка ответа в нужный чат и ошибки Telegram API.
- настройки города по умолчанию в SQLite;
- `/setcity`, `/city`, `/weather` с аргументом и без аргумента;
- эмодзи в Telegram-выводе.
- регистрацию меню команд Telegram.
- постоянную reply-клавиатуру через `reply_markup`;
- сценарий настройки города через кнопку и следующее текстовое сообщение.
- настройку ежедневной отправки через `/settime` и кнопку;
- отключение ежедневной отправки;
- выбор due-пользователей по timezone города;
- защиту от повторной ежедневной отправки через `last_notification_date`.
- обновление отсутствующего timezone при настройке рассылки.

## Рекомендации для будущих изменений

- Не добавлять внешние зависимости без необходимости: текущий скрипт работает на стандартной библиотеке.
- Не делать реальные сетевые запросы в unit-тестах.
- При изменении правил ввода обновлять и `validate_city_name`, и тесты рядом с ним.
- При добавлении новых погодных полей обновлять `get_weather`, `format_weather`, тесты и пример вывода.
- При изменении пользовательских сообщений обновлять тесты, которые проверяют текст ошибок.
- Не хранить Telegram token в репозитории, логах или документации.
- Не коммитить SQLite-файл из `data/`.
- При развитии автодоставки не ломать `notification_enabled`, `notification_time`,
  `timezone`, `last_notification_date`, сохраненные `default_city` и координаты.
